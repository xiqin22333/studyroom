        校园自习室预约管理系统 —— 预约管理模块使用说明书
================================================================================

【一句话说明】
预约管理是整个系统的"核心业务"模块：学生选座位、选时段发起预约，
到馆签到、离开签退，管理员维护预约规则和时段。预约规则和冲突检测
都在这里实现。

--------------------------------------------------------------------------------
一、包含哪些表，各干什么
--------------------------------------------------------------------------------
表名                作用                                            举例
----------------------------------------------------------------------
reservation         预约记录表：一条记录=一次预约                      明天上午预约A101-01
reservation_rule    预约规则表：全局规则（每天约几次、能约几天后等）    默认规则：每天3次、提前7天
time_slot           预约时段表：可选的时段（上午/下午）                 上午 08:00-12:00
checkin_record      签到记录表：签到/签退的时间记录                     08:05 签到，11:50 签退

关系：
    time_slot（时段） ──┐
    seat（座位）       ──┼──> reservation（预约）──> checkin_record（签到记录）
    user（用户）       ──┘         │
                                  └──> reservation_rule（规则，预约时校验用）

--------------------------------------------------------------------------------
二、预约的完整流程（状态怎么变化）
--------------------------------------------------------------------------------
  [发起预约]      [签到]       [签退]
  状态0 待签到 ──> 状态1 已签到 ──> 状态2 已完成
      │
      └──> 状态3 已取消（用户主动取消）
      └──> 状态4 爽约（预约了没来，需定时任务处理，暂未实现）
      └──> 状态5 违规取消（信用模块处理，暂未实现）

--------------------------------------------------------------------------------
三、接口清单（怎么用）
--------------------------------------------------------------------------------
【预约核心】/api/reservation/reservation
  POST  （发起预约）      请求体见下面例子
  POST  /cancel/{id}?reason=临时有事      取消预约（仅"待签到"可取消）
  POST  /checkin?reservationId=1&checkinType=3   签到（待签到→已签到）
  POST  /checkout?reservationId=1        签退（已签到→已完成）
  GET   /my?userId=4&status=0            我的预约（status可不传=全部）
  GET   /occupied?roomId=1&date=2026-09-18&seatId=&slotId=   查哪些被占了
  GET   /page                            管理员分页看全部预约
  GET   /{id}                            查单个预约

  发起预约示例：
  POST /api/reservation/reservation
  {
    "userId": 4,              // 谁预约（学生ID）
    "roomId": 1,              // 自习室ID
    "seatId": 1,              // 座位ID
    "slotId": 1,              // 时段ID（选了时段就不用传起止时间）
    "reserveDate": "2026-09-18"  // 预约日期
  }
  成功返回：预约编号 reservationNo（自动生成）、状态 0（待签到）、签到码

【预约规则】/api/reservation/rule
  GET   /page                分页查规则
  GET   /{id}                按ID查
  POST  （新增规则）          例：{"ruleName":"默认规则","ruleCode":"DEFAULT",
                                 "maxReservePerDay":3,         每天最多3次
                                 "maxReserveDuration":480,     单次最长480分钟
                                 "advanceReserveDays":7,       最多提前7天约
                                 "creditThreshold":60,         信用分≥60才能约
                                 "status":1}
  PUT   （修改规则）
  DELETE /{id}               删除规则

【预约时段】/api/reservation/time-slot
  GET   /page /{id}          查询
  POST  （新增时段）          例：{"slotName":"上午","startTime":"08:00","endTime":"12:00","maxReserve":100,"status":1}
  PUT   （修改时段）
  DELETE /{id}               删除时段

【签到记录】/api/reservation/checkin
  GET   /page                分页查签到/签退记录（谁、几点签到、几点签退）
  说明：正常签到请用 /api/reservation/reservation/checkin，这里只是查记录

四、预约时系统自动做了什么（看懂代码用）
--------------------------------------------------------------------------------
发起预约时，后端依次检查（顺序很重要）：
  1. 用户存在、账号可用
  2. 座位存在、座位可用（status=1）
  3. 时段有效（选了时段的话）
  4. 规则校验（读 reservation_rule 第一条启用规则）：
     - 信用分是否达到阈值（credit_threshold）
     - 日期不能是过去、不能超过可提前天数
     - 当天预约次数是否超上限
     - 时长是否超上限
  5. 冲突检测：同一个座位、同一天、时间有重叠的有效预约 → 拒绝
     （"有效"= 状态 0待签到/1已签到/2已完成，取消的不算）
  6. 生成预约编号（RS+时间戳+随机数）和签到码，状态置为 0 待签到

  看代码：ReservationServiceImpl 的 createReservation 方法

七、常用问题
--------------------------------------------------------------------------------
Q：提示"该座位在所选时段已被预约"？
A：这是冲突检测在起作用，换一个座位或时段即可。

Q：提示"当天预约次数已达上限"？
A：规则里 maxReservePerDay=3，取消的预约不占次数，第二天自动恢复。

Q：签到提示"当前状态不可签到"？
A：只有"待签到"状态的预约能签到；已签到/已完成/已取消都不能重复操作。

Q：怎么改预约规则？
A：用 PUT /api/reservation/rule 修改规则（或直接改数据库 reservation_rule 表）。

Q：爽约（约了不来）和违规取消怎么触发？
A：这两个状态（4/5）需要定时任务和信用模块配合，属于下一步开发内容。
