================================================================================
        校园自习室预约管理系统 —— 系统模块使用说明书
================================================================================

【一句话说明】
系统模块是整套系统的"后台管理"部分，负责管人（用户）、管角色、
管系统参数、记操作日志。其它模块（场地、预约、信用、通知）都是
在它的基础上展开的。

--------------------------------------------------------------------------------
一、系统模块包含哪些表，各干什么
--------------------------------------------------------------------------------
表名            作用                                      举例
----------------------------------------------------------------------
sys_user        用户表：存所有账号（学生/教师/管理员）      admin 账号
sys_role        角色表：定义"身份"                         管理员、教师、学生
sys_user_role   中间表：用户和角色是多对多关系               一个用户可以有多个角色
sys_config      系统配置表：存一些可以随时改的参数           初始信用分=100
operation_log   操作日志表：自动记录谁在什么时候干了什么     登录、新增用户都会记

关系图：
    sys_user  ──┐
                ├── sys_user_role（中间表）── sys_role
    一个用户可以有多个角色，一个角色也可以给多个用户

三、接口清单（怎么用）
--------------------------------------------------------------------------------
所有接口统一返回格式：
    {"code":200,"message":"操作成功","data":...}
    code=200 成功；code=400 参数错；code=401 未登录；code=500 业务/系统错误

【1. 登录】POST /api/system/auth/login
    请求体：{"username":"admin","password":"123456"}
    返回：用户信息 + 角色列表
    注意：密码正确才能登录；账号被禁用会提示"账号已被禁用"

【2. 用户管理】/api/system/user
    GET    /page            分页查用户（可加 ?keyword=张三 模糊搜索）
    GET    /{id}            查单个用户（带角色ID）
    GET    /{id}/roles      查某用户的角色ID列表
    POST   （新增用户）      请求体见下面例子
    PUT    （修改用户）      传了密码才改密码；传了roleIds才重新分配角色
    DELETE /{id}            删除用户（逻辑删除，数据还在库里，只是打上删除标记）
    POST   /reset-password?id=1&newPassword=888888   重置密码
    PUT    /status?id=1&status=0                     启用(1)/禁用(0)账号

    新增用户示例：
    POST /api/system/user
    {
      "username": "zhangsan",      // 登录名，必填，不能重复
      "passwordHash": "abc123",    // 密码，不传默认 123456
      "realName": "张三",          // 真实姓名
      "studentNo": "20240001",     // 学号/工号
      "userType": 1,               // 1学生 2教师 3管理员
      "phone": "13800000000",      // 手机号（可不填）
      "email": "zs@xx.com",        // 邮箱（可不填）
      "college": "计算机学院",      // 学院（可不填）
      "major": "软件工程",          // 专业（可不填）
      "className": "软件2401",      // 班级（可不填）
      "creditScore": 100,          // 信用分，不传默认100
      "status": 1,                 // 1正常 0禁用，不传默认1
      "roleIds": [3]               // 给这个用户分配的角色ID数组（可多个）
    }

【3. 角色管理】/api/system/role
    GET    /page            分页查角色
    GET    /list            查全部启用角色（给用户分配角色时用的下拉列表）
    GET    /{id}            查单个角色
    POST   （新增角色）      例：{"roleCode":"MANAGER","roleName":"楼栋管理员","status":1}
    PUT    （修改角色）
    DELETE /{id}            删除角色

【4. 系统配置】/api/system/config
    GET    /page            分页查配置
    GET    /key/{key}       按配置键查，如 /key/credit.init
    GET    /{id}            按ID查
    POST   （新增配置）      例：{"configKey":"credit.init","configValue":"100","description":"初始信用分"}
    PUT    （修改配置）
    DELETE /{id}            删除配置

【5. 操作日志】/api/system/operation-log
    GET    /page            分页查日志（谁、什么时候、做了什么操作、请求参数、返回结果）
    说明：不用手动写日志！只要在 Controller 方法上标了 @OperLog(module=,action=)，
          系统会自动把这次操作记进 operation_log 表（登录、新增用户等已自动标注）

四、几个重要的设计说明（看懂代码用）
--------------------------------------------------------------------------------
1. 密码怎么存？—— 不存明文，存 SHA-256 加密后的"密码摘要"。
   登录时把用户输入的密码加密后再比对。这样数据库泄露也不会直接暴露密码。
   （学习项目用 SHA-256 简化，正式项目建议换 BCrypt）
   看代码：SysUserServiceImpl 里的 encodePassword 方法

2. 删除用户为什么数据还在？—— 这叫"逻辑删除"。
   sys_user 表有 deleted_at 字段，删除时只是给它写上当前时间，查询时自动过滤
   掉带删除时间的记录。好处：误删可以恢复，操作可追溯。
   看代码：SysUser 实体里 deletedAt 字段上的 @TableLogic 注解

3. 操作日志为什么"自动"？—— 用了 Spring AOP（面向切面编程）。
   在要记录的方法上标 @OperLog 注解，切面 OperationLogAspect 会自动拦截
   并记录。改一行注解就能给新接口加日志。
   看代码：annotation/OperLog.java + aspect/OperationLogAspect.java

4. 用户怎么分配角色？—— 用户表存账号信息，角色ID存在中间表 sys_user_role。
   新增/修改用户时传 roleIds 数组，程序会先删掉旧角色再插入新角色。
   看代码：SysUserServiceImpl 里的 saveUserRoles 方法

五、怎么验证系统好不好用（动手试一遍）
--------------------------------------------------------------------------------
1. 在 IDEA 里启动项目（右上角 Run，等日志出现"Tomcat started on port 8080"）
2. 打开浏览器访问：http://localhost:8080/   （能看到欢迎页=服务正常）
3. 用 Postman 或浏览器测试：
   - 登录：POST http://localhost:8080/api/system/auth/login
            body: {"username":"admin","password":"123456"}
            → 返回 code=200 就是登录成功
   - 看用户列表：GET http://localhost:8080/api/system/user/page
   - 新增一个用户：POST http://localhost:8080/api/system/user
   - 看操作日志：GET http://localhost:8080/api/system/operation-log/page
            会发现登录、新增用户都被自动记下来了

六、常用问题
--------------------------------------------------------------------------------
Q：登录提示"用户名或密码错误"？
A：确认账号存在、密码正确；账号被禁用也会被拒（提示"账号已被禁用"）。

Q：我新增的用户查不到？
A：确认是不是被删过（逻辑删除后列表不再显示）；删除过的用户名不能重复注册。

Q：操作日志里没记录？
A：只有标注了 @OperLog 注解的接口才会记录。没标注的接口不记。

Q：以后怎么加权限控制（比如只有管理员能删用户）？
A：这是下一步：登录时拿到的 roles 角色列表，配合拦截器校验即可。
   目前接口没有做登录拦截，属于开发阶段，方便你测试。
